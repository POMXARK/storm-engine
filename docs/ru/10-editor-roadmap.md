## Этап 1 — сцена управляется из скрипта (готово)

Сейчас скрипт видит только маркеры (`GetSceneMarker`): модель сцены нельзя спрятать, сдвинуть или переключить ей анимацию, а зону «игрок вошёл» приходится считать вручную. После этапа уровень собирается в редакторе, а скрипт только реагирует.

### 1.1 Объекты сцены из скрипта — модуль `scene`

- [x] Библиотека `SceneObjects` (`scene_library.cpp`). Она отдельная от `SceneLibrary` и `SceneMarkers`, так что старые скрипты не ломаются: библиотека требует объявить все свои функции (03).
  - `int SceneObjectAction(string name, string action)` — действие анимированной модели (`MSG_MODEL_PLAY_ACTION`, проигрыватель 0).
  - `int SceneObjectShow(string name, int show)` — модель прячется и показывается (слой `REALIZE`), звук останавливается и играет снова.
  - `int SceneObjectMove(string name, float x, float y, float z, float ay)` — новое место (`WritePlace`).
  - Возвращают 1, если объект найден, иначе 0.
- [x] В `SceneObject` появляется поле `hidden` (не пишется в файл). Stop в редакторе откатывает изменения по снимку сцены.

### 1.2 Триггер-зоны

- [x] `[[trigger]]` в `.scene` — маркер с `radius` и `height`: вертикальный цилиндр от точки маркера вверх. Разбор и запись, тест в `scene-test`.
- [x] `int CheckSceneTriggers(string who, float x, float y, float z)` — скрипт вызывает из своего тика с позицией того, за кем следит (персонаж — `MSG_CHARACTER_GETPOS`, корабль — его атрибуты). Модуль помнит, в каких зонах сейчас каждый `who`, и при переходе через границу посылает события `SceneTriggerEnter` и `SceneTriggerExit` с аргументами `(string trigger, string who)`. Возвращает число зон, где сейчас `who`.
  - Почему позицию даёт скрипт: модуль `scene` не зависит от `location` и `sea`, так одни и те же зоны работают для персонажей, NPC и кораблей.
- [x] `LoadScene` и `ClearScene` сбрасывают, кто в каких зонах.
- [x] Редактор: кнопка **Add trigger**, свойства **Radius** и **Height**, зелёный цилиндр на Viewport (два кольца и четыре стойки), в списке — зелёная пометка `trigger`.

### 1.3 Горячие клавиши

- [x] Del — удалить, Ctrl+D — дублировать, Ctrl+Z/Y — отмена, Ctrl+S — сохранить (уже были).
- [x] **W** — перенос, **E** — поворот (R оставлена под масштаб, этап 2).
- [x] **F** — свободная камера подлетает к выбранному объекту и смотрит на него.
- [x] **Esc** — снять выделение.
- [x] Клавиши срабатывают, только когда в фокусе Viewport или Scene, правая кнопка не зажата (с ней W — полёт камеры) и курсор не в поле ввода.

### 1.4 Демо `demos/trigger`

- [x] Двор и матрос на ассетах `demos/melee`. Матрос сам ходит между маркерами `a` и `b` (`Goto point`), клавиши не нужны.
- [x] Зона `gate` между маркерами. При входе стражник встаёт в стойку, колокол звенит, ящик прячется. При выходе всё возвращается. Каждое событие пишется в `Trace`.
- [x] Проверка: `error.log` пуст, в `compile.log` есть чередование `enter`/`exit`.

## Этап 2 — правка сцены

- [ ] Масштаб в гизмо (R) и ключ `scale` в `.scene`.
- [ ] Выбор нескольких объектов: Shift/Ctrl-клик, рамка. Перенос, поворот, удаление и дублирование группы.
- [ ] Привязки: положить на поверхность под объектом (луч вниз по BSP), шаг сетки уже есть в Gizmo.
- [ ] Окружение сцены: блок `[environment]` в `.scene` (солнце, туман, небо, цвет фона) и его окно.
