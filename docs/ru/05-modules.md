# 5. Модули движка (`S/src/libs/`)

| Модуль | Назначение |
|---|---|
| `core` | цикл, компилятор/VM, сущности, слои, события, file service, engine settings, config |
| `util`, `math`, `shared_headers`, `diagnostics`, `config` | утилиты, вектора/матрицы, общие с скриптами заголовки, логи/sentry, LoadConfig |
| `window`, `input`, `pcs_controls` | SDL-окно, ввод, PC-контролы (класс `controls` в engine.ini) |
| `renderer` | DX9 (на Linux — через dxvk-native, см. [08-linux-build.md](08-linux-build.md)), текстуры, техники, шрифты, скриншоты, видео-текстуры |
| `sound`, `sound_service` | звук: алиасы, схемы, 3D, бэкенд miniaudio/FMOD |
| `xinterface` | GUI: узлы, экраны, строки, aviplayer |
| `geometry`, `model`, `animation` | .gm, модели-сущности, скелетная анимация |
| `collide` | столкновения, трассировка лучей |
| `location`, `locator`, `lighter`, `blade`, `blot`, `teleport`, `animals` | сухопутные локации, персонажи, локаторы, освещение, оружие, кровь |
| `sea`, `ship`, `sea_ai`, `sea_cameras`, `sea_operator`, `sea_creatures`, `sea_foam`, `water_rings`, `ball_splash`, `sink_effect`, `sailors` | море, корабли, ИИ, камеры, эффекты, матросы |
| `rigging`, `mast` | паруса, канаты, флаги, мачты |
| `island`, `weather`, `tornado`, `shadow`, `touch` | острова, погода/небо/звёзды/дождь, смерчи, тени, касания кораблей |
| `worldmap` | глобальная карта |
| `battle_interface` | боевой HUD |
| `dialog` | диалоги |
| `particles` | системы частиц (.xps) |
| `script_library` | мелкие нативные функции для скриптов |
| `steam_api` | Steam |
| `editor` | встроенный редактор (`--editor`): ImGui поверх кадра через d3d9 (на Linux — dxvk-native), окна инструментов `RegisterEditorTool`, их состояние в `imgui.ini` (рецепт 6.21) |
| `src/apps/configapp` | отдельная утилита настроек |

Корабль (проверено в `demos/ship`, рецепт 6.10): сущность `ship` (корпус, ход, качка; события `SeaGetLayers`, `Shp_UpdParams`, `ShpCreate`, `Ship_StartLoad/EndLoad`), `sail` из `rigging` (паруса, их анимация по ветру из `Weather.Wind.*`), `SEA_CAMERAS` + `SHIP_CAMERA` из `sea_cameras` (камера вокруг корабля, `AI_CAMERAS_SET_CAMERA 55001`; атрибут `Target` — индекс персонажа, чей корабль камера держит в кадре, 6.10). Нужны также `weather`, `sky`, `sea` из 6.9.

Частицы (проверено в `demos/particles`, рецепт 6.11): сущность `particles` создаёт системы из `resource\particles\*.xps` (4.11) сообщением `PS_CREATE 10000` и рисует их после всего остального. Указатель на систему, который возвращает `PS_CREATE`, 64-битный — в int скрипта не помещается, поэтому системы удаляются через захват: `PS_CREATIONCAPTURE_BEG/END 10011/10012` и `PS_CLEAR_CAPTURED 10013` (или все сразу — `PS_CLEARALL 10006`).

Диалоги (проверено в `demos/dialog`, рецепт 6.12): сущность `dialog` (класс `DIALOG`; `LegacyDialog` — для старых скриптов) рисует окно по `dialog.ini` (4.12) с текстом из своих атрибутов `Text` и `Links.*`, сама листает страницы и выбирает ответ контролами `Dlg*`. Дерево реплик — целиком в скрипте: на выбор ответа движок пишет `CurrentNode` и шлёт событие `DialogEvent`, скрипт заменяет `Text` и `Links`. На время открытия ставит `SetTimeScale(0)` и плавно возвращает 1 за секунду.

Сохранения (проверено в `demos/save`, рецепт 6.13): `core`. `SaveEngineState(file)` вызывает в скрипте `OnSave()` и сразу пишет все глобальные переменные с атрибутами (4.13). `LoadEngineState(file)` только запоминает файл (если он есть); в начале следующего кадра движок удаляет все сущности, заново компилирует программу, восстанавливает переменные и вызывает `OnLoad()` вместо `Main()`. Обработчики событий при этом сброшены, контролы (`CreateControl`/`MapControl`) — нет. Сущность сама положение в файл не пишет; у корабля оно и так лежит в атрибутах персонажа (`ship.pos`, `ship.ang` — ship.cpp обновляет их каждый кадр), а состояние, которое живёт только внутри сущности (паруса), скрипт копирует в переменную в `OnSave`. Экран сохранений игры (`SAVE_FILE_FIND`, скриншот через `SCRSHOTER`) — в `xinterface`, демо обходится без него.

Морской бой (проверено в `demos/battle`, рецепт 6.15): ядра — сущность `AIBalls` из `sea_ai` (4.10.1), она летит, рисует и трассирует ядра; попадания разбирает `ship` и шлёт события скрипту, дыры в парусах делает `sail`, пробоины — `blots` (её создаёт корабль). `AIBalls` берёт рендер из `AIHelper::pRS`, а его ставит только `SEA_AI::Init`, поэтому `SEA_AI` нужно создать, даже если ИИ не используется. Потопить корабль без `SEA_AI` можно сообщением `MSG_SHIP_SET_DEAD 50316` (добавлено для демо): корабль тонет, уходит под воду и шлёт `ShpDelete` "li".

ИИ кораблей (проверено в `demos/ai-ship`, рецепт 6.16): сущность `SEA_AI` из `sea_ai`. Корабли добавляются в группы (`AI_MESSAGE_GROUP_SET_COMMANDER`, `GROUP_SET_XYZ_AY`, `ADD_SHIP`), задачи — `AI_MESSAGE_SHIP_SET_TASK` (атака, бегство, движение, дрейф). Для не-главного персонажа SEA_AI сама ведёт корабль (`AIShipMoveController`, скорость, поворот, обход касаний) и стреляет, когда борт достаёт цель (`AIShipCannonController`); у главного (`MainCharacter`) только стреляет по `AI_MESSAGE_CANNON_FIRE`. Отношения, перезарядку, высоту прицела и прочие числа она спрашивает у скрипта событиями, а сам выстрел отдаёт скрипту событием `CannFire` — ядро создаёт скрипт через `AIBalls` (4.10.1, 4.10.2). Атрибут `Ship.Cannons.Aim` персонажа включает зону прицела на воде (6.10).

Остров (проверено в `demos/island`, рецепт 6.17): сущность `island` грузит модель суши и дна и карту глубин (4.14), рисует их и отвечает на запросы глубины (`GetDepth`, `Check2DBoxDepth`) и трассировки (`Trace`, `Cannon_Trace`). Кто ею пользуется:
- `touch` каждый кадр сверяет точки по контуру корпусов с картой. Корабль, чей корпус дошёл до глубины `Touch.CollisionDepth`, отталкивается от берега, и приходит `Shp_ShipIslColl` "llfflfff" (корабль, −1 для острова, сила удара в узлах, доля скольжения 0..1, точка корпуса, x/y/z). Урон считает скрипт.
- `ship` сообщает о мели под килем событием `Shp2Strand` "ll" (корабль, 1/0).
- `SEA_AI` не ставит корабли на мель, обходит сушу по графу из ini карты и бьёт только с воды глубже −4.
- `AIBalls` при попадании ядра в модель шлёт `Ball_IslandHit` "lfff" (владелец, точка), камера корабля не уходит в сушу.
`island`, `SEA_AI` и `touch` находят друг друга и корабли при создании, поэтому порядок такой: остров → `SEA_AI` → `touch` → корабли.

Боевой HUD (проверено в `demos/hud`, рецепт 6.18): сущность `battle_interface` (`BATTLE_INTERFACE`, `sea/i_battle.cpp`). Все настройки она читает из своих атрибутов в `Init`, поэтому их задают до `CreateEntity`. Внутри три части:
- `BATTLE_NAVIGATOR` — навигатор: мини-карта (на первом кадре сам находит сущность `island` и рендерит её модель сверху в текстуру), корабли и их зоны огня, компас и стрелка ветра, дуги заряда бортов, скорости ветра и корабля, иконки.
- `BIShipIcon` — панель кораблей игрока: картинка, имя, экипаж, полоски HP и SP. Её рисует меню команд, поэтому без `ShowCommands = 1` панели нет.
- `BIShipCommandList` — меню команд; открывается контролом `BI_COMMANDS_ACTIVATE_SEA`.
Корабли HUD берёт из своего списка, который заполняет скрипт сообщением `BI_IN_CREATE_SHIP 46011` (сущность `ship` ищется по `index` персонажа). Числа — из атрибутов: HP/SP и экипаж из `character.Ship.*`, максимумы из базового корабля, заряд бортов из `Ship.Cannons.Borts.*` (их пишет `SEA_AI`), зоны огня из `BaseShip.Cannons.Borts.*`, ветер из `weather`. Иконки заряда, парусов и ветра выбирает скрипт в ответ на событие `GetCurrentCharge`; необязательный шестой элемент — число зарядов под иконкой (6.18).

Ближний бой (проверено в `demos/melee`, рецепт 6.19): `location` + `blade` + `CharactersGroups`. Боевой автомат живёт в `Character` (`character.cpp`): режим боя, выбор атаки, блок, парирование, реакции на попадание, поиск задетых при событии анимации `Attack` (`Supervisor::FindCharacters`, по умолчанию 2.4 м и ±60°, `data = "Dist"`/`"Ang"` в действии). Задетым считается только враг по `CharactersGroups`. Сущность `blade` создаёт сам персонаж на `MSG_CHARACTER_SETBLADE`, она держит модель сабли на метке `saber_hand` или `saber_belt` и рисует след. ИИ (`NPCharacter::FightTick`) раз в 0.2 с выбирает атаку или защиту по весам из событий `NPC_Event_*`. Жизнь, энергию и урон движок не хранит — их ведёт скрипт, отвечая на события (таблица в 6.19). Полосы над врагом рисует `location` (`LocEfx\state_bars.tga`), если персонаж враг игрока и в режиме боя.

Звук (проверено в `demos/sound`, рецепт 6.14): сущность `Sound` из `sound` — тонкая обёртка над сервисом `sound_service`, сообщения 77001–77031 (4.7). Сервис сам держит слушателя на камере, кэширует сэмплы, ведёт два слота музыки с кроссфейдом, алиасы (`resource\ini\aliases\*.ini`, читаются при старте) и фоновые схемы; события `SoundEnded` шлёт по окончании звука. Бэкенд — `storm::audio` (miniaudio или FMOD, 08-linux-build.md §7).

Глобальная карта (проверено в `demos/worldmap`, рецепт 6.20): сущность `worldmap` (`WorldMap`) — замкнутый мир. Внутри неё:
- море, острова и их названия;
- корабль игрока с кильватером, камера;
- тучи, грозы, часы с небом суток, ветер, компас.

С внешними сущностями (`sea`, `weather`, `SEA_AI`) она не связана. Скрипт задаёт старт, дату и параметры через атрибуты до `CreateEntity` и отвечает на события. Раз в секунду приходит `WorldMap_EncounterCreate` (dt, x, z, ay), на него скрипт расставляет встречи и штормы сообщениями `MSG_WORLDMAP_CREATE*`. Корабль игрока сообщает о встречах событиями:
- `WorldMap_ShipEncounter` — догнал враг;
- `WorldMap_PlayerInStorm` — корабль в шторме;
- `ExitFromWorldMap` — выход в море по Enter.

Мораль и провиант для плашки берутся из ответов на `WorldMap_GetMoral`/`GetFood`/`GetRum`. Атрибут `worldMap.autopilot.x/z` (добавлен для демо) ведёт корабль к точке без клавиатуры.

Для своей игры достаточно `core`, `renderer`, `xinterface`, `sound_service`, `pcs_controls` (это подтверждает `tools/menu-demo`). Морские и сухопутные модули подключаются, только если скрипт создаёт их сущности.
